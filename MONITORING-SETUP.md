# Monitoring setup

The caregiver chooses a home center and a radius. The center stays there until
they change it; it does not follow the caregiver phone. Positions are latitude
and longitude in degrees; radius and distance are meters. Local Bluetooth x/y
coordinates must be converted by the positioning integration before sending.

## Database

Back up existing data before migrations. Do not rerun old migrations.

- New Supabase project only: run `supabase/simple-schema.sql`, followed by the
  migrations below in filename order. The initial file is a historical baseline.
- Existing project with latitude/longitude and current status already installed:
  run only `supabase/migrations/20261012_notification_delivery.sql`.
- Earlier installations: review `20261010_current_status.sql` (removes the empty
  incidents table) and `20261011_latitude_longitude.sql` (clears old local
  coordinates), then run the notification migration.

There is no incident history. `notification_outbox` holds temporary delivery jobs
so failed network requests can retry. Successful receipts delete the job; jobs
expire after an hour or eight failures. It is inaccessible to phone clients.
No migration is applied by starting the app or saving these files.

Create test caregivers in Supabase Authentication. Provision a fictional patient,
its `caregiver_patients` assignment and a `devices` row in the SQL Editor. Pairing
and recording screens are still placeholders; they do not perform provisioning
or upload audio. Do not insert passwords into application tables.

## Backend

From `backend`, run `npm ci`, copy `.env.example` to `.env`, and fill in your
existing project values and device secret. Never commit `.env`.
Database TLS certificates are verified. If needed, download the CA from your
Supabase database settings and set `DATABASE_CA_FILE` to its local path; do not
disable verification. Start with `npm start`. Startup checks required tables.

Keep the backend running: it checks every 5 seconds, and marks a watch lost at
60 seconds without an accepted position (up to another 5 seconds to detect it).
The polling interval is not a 5-second disconnect timeout. No fresh position
and an offline watch currently share the disconnected status; the API cannot
distinguish dead battery, Wi-Fi loss or a stalled positioning source.

## App

Set `EXPO_PUBLIC_API_URL` in `frontend/.env.local` to the laptop's reachable LAN
address and backend port, alongside the Supabase URL/publishable key. Use HTTPS
for deployment. Run `npm ci` then `npx expo start` from `frontend`.

Sign in, open Status, Find an address, confirm the returned location, and save a
radius. Phone location is used only after pressing that button; it does not
track the patient. Address lookup uses Nominatim with caching and a single
request queue. Run one backend instance with the public provider; set
`GEOCODING_URL` and `GEOCODING_USER_AGENT` for a different compatible provider.

## Push alerts

The app has explicit Enable/Disable controls in Settings. A development build,
an EAS project ID in `extra.eas.projectId`, and platform push credentials are
required. Follow Expo's push setup documentation. No project ID or credentials
are generated by this change. Expo Go can test the Status screen, not this push
flow. Rebuild the native app after changing notification/location plugins.

Enable alerts on the caregiver phone. Logout unregisters its token first, so it
requires the backend to be reachable when a token is registered. Queue retries
are at least once: rare duplicate notifications are possible after a lost
response. A push receipt confirms provider acceptance, not that a person saw it.

## Watch and demo checks

See `watch/README.md` for the Linux reference client and the optional buzzer
endpoint adapter. `careQ/` is deliberately unchanged.

For a simulated walk, from `backend`:

```sh
node --env-file=.env scripts/simulate-watch.js DEVICE_UUID walk
```

One update every 10 seconds. Stop it to test loss after 60 seconds. Test inside,
outside, return, pause, cancel a pending pause, resume and silence. Disconnect
the watch while applying a control: the app must show pending until it receives
the exact acknowledged settings version. Reconnecting outside is still outside.

Automated checks:

```sh
# backend
npm test
# frontend
npx tsc --noEmit
npm run lint
# watch
python -B -m unittest discover -s . -p "test_*.py"
```

This prototype uses exact distance comparisons, without positioning uncertainty
or boundary hysteresis. Noisy coordinates can alternate inside/outside. Hardware
positioning, recorded speech, device pairing, and closed-app push delivery need
real-device integration tests; unit tests do not establish those work.
